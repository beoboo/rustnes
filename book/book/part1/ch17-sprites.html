Build Your Own NES Emulator

Sprites

The arena is haunted, and you’ve felt it from both sides: gems eaten by nothing, lives taken by nothing. Time to meet the nothing. Backgrounds can only paint a grid — every tile nailed to its cell, moved only by rewriting the map. But a hero slides between cells, glides over the scenery, overlaps it. For things that move, the PPU has a second drawing system: sprites — up to sixty-four little pictures, each floating free at any pixel on the screen.

Sixty-four little forms

The PPU keeps its cast list in a memory of its own: OAM, Object Attribute Memory — 256 bytes, four per sprite. Four bytes is a whole character sheet:

The Y byte carries a famous quirk: the hardware draws every sprite one row lower than the byte says, so games store “top minus one” and nobody talks about it. It also gives games a free trick — write $EF or anything below it and the sprite starts past row 239: parked off the bottom of the world, invisible. An empty cast list is 64 sprites in the parking lot.

Of the attribute bits, our games use exactly two: the palette pick. The flips, and “behind the scenery”, stay dark in both Chase and Lan Master from boot to game over — so today they stay dark in our code too, and the Try It below dares you to light one.

The memory itself, in ppu.rs under palette_ram:

src/ppu.rs

/// The eight palettes — 32 bytes the games fill at boot.
pub palette_ram: [u8; 32],

/// The sprite roster — OAM, Object Attribute Memory: 64 sprites,
/// four bytes each. Games rebuild all 256 bytes every frame.
pub oam: [u8; 256],

/// PPUCTRL, as last written: a byte of settings.
pub ctrl: u8,

The fast lane

How does a game fill it? Sixty-four moving things per frame through a one-byte-at-a-time register would eat the whole vblank. So the console installed a fire hose: the game lays out all 256 bytes in ordinary RAM — a private copy it can scribble on all frame long — then writes the page number to $4014, and the hardware copies the entire page into OAM in one gulp. Chase does exactly this on every single NMI: rebuild the roster in RAM at $0200, then $4014, done.

In the bus’s write, after the controller’s arm:

src/bus.rs

// The controller's strobe line.
0x4016 => self.controller.write(value),

// Sprite memory's fast lane: one write here streams a
// whole 256-byte page of RAM into OAM. On hardware the
// CPU stands still for 513 cycles while it flows; ours
// is instant, and that debt is on the books for Part II.
0x4014 => {
    let base = (value as u16) << 8;
    for offset in 0..256u16 {
        let byte = self.read(base + offset);
        self.ppu.oam[offset as usize] = byte;
    }
}

// Writes to ROM change nothing. The clue is in the name.
0x8000..=0xFFFF => {}

(Games also poke $2003 first — OAMADDR, “start the copy at slot zero”. They always say zero, our copy always starts at zero, and the write falls into the PPU stub arm politely. If a game ever asks for something stranger, we’ll hear about it.)

Drawing them

Painting the cast is chapter 13’s tile decoding wearing three new rules. Rule one: sprites draw over the finished background, and earlier roster slots beat later ones — sprite 0 is the front of the stage. Walking the roster back to front gets both for free. Rule two: color 0 of a sprite’s palette isn’t a color, it’s a hole — the scenery shows through, which is why a round face can ride on a square tile. Rule three: PPUCTRL bit 3 says which half of the album the cast wears, and games flip that bit live — Chase’s walking animation is nothing but this, the whole cast changing costume eight frames at a time.

At the bottom of main.rs, after background_palette — the painter and its little crayon helper:

/// Paint the 64 sprites over the finished background, roster's back
/// to roster's front, so sprite 0 wins every overlap.
fn render_sprites(cpu: &Cpu, buffer: &mut [u32]) {
    let ppu = &cpu.bus.ppu;
    let chr = &cpu.bus.cartridge.chr_rom;

    // PPUCTRL bit 3: which half of the album holds sprite tiles.
    // Games flip this bit to animate their whole cast at once.
    let table = if ppu.ctrl & 0b0000_1000 != 0 { 256 } else { 0 };

    for sprite in ppu.oam.chunks(4).rev() {
        let (top, tile, attributes, left) =
            (sprite[0], sprite[1], sprite[2], sprite[3]);

        // Parking a sprite at the bottom edge is the "I'm not here"
        // convention: anything from $EF down starts past row 239.
        if top >= 0xEF {
            continue;
        }

        let pixels = ppu::decode_tile(chr, table + tile as usize);
        let palette = sprite_palette(ppu, attributes);

        for (row, line) in pixels.iter().enumerate() {
            // Hardware draws every sprite one row below its stored
            // Y — games store "top minus one" and know it.
            let y = top as usize + 1 + row;
            if y >= HEIGHT {
                break;
            }

            for (col, &value) in line.iter().enumerate() {
                // Color 0 is a hole: the scenery shows through.
                if value == 0 {
                    continue;
                }
                let x = left as usize + col;
                if x >= WIDTH {
                    break;
                }
                let crayon = palette[value as usize];
                buffer[y * WIDTH + x] = ppu::SYSTEM_PALETTE[crayon as usize];
            }
        }
    }
}

/// A sprite's four crayons: attribute bits 0-1 pick one of the four
/// sprite hands, the upper half of palette RAM. Slot 0 is listed only
/// to keep the indexing honest — sprites never paint with it.
fn sprite_palette(ppu: &ppu::Ppu, attributes: u8) -> [u8; 4] {
    let which = (attributes & 0b11) as usize;
    let base = 0x10 + which * 4;

    [
        0,
        ppu.palette_ram[base + 1],
        ppu.palette_ram[base + 2],
        ppu.palette_ram[base + 3],
    ]
}

Did it work?

Two robots for the fire hose, at the end of cpu.rs’s tests:

src/cpu.rs

        while cpu.step() {}
        assert_eq!(cpu.a, 0);
    }

    #[test]
    fn a_write_to_4014_copies_a_whole_page_into_oam() {
        let mut cpu = Cpu::new(test_cartridge(&[0x00]));
        for i in 0..=255u8 {
            cpu.write(0x0200 + i as u16, i);
        }

        cpu.write(0x4014, 0x02);

        assert_eq!(cpu.bus.ppu.oam[0], 0);
        assert_eq!(cpu.bus.ppu.oam[137], 137);
        assert_eq!(cpu.bus.ppu.oam[255], 255);
    }

    #[test]
    fn dma_reads_travel_through_the_bus() {
        // Page $08 is an echo of page $00 — the RAM mirrors from
        // chapter 11. A copy that grabbed at raw memory would miss it.
        let mut cpu = Cpu::new(test_cartridge(&[0x00]));
        cpu.write(0x0000, 0xAB);

        cpu.write(0x4014, 0x08);

        assert_eq!(cpu.bus.ppu.oam[0], 0xAB);
    }
}

The second is the sneaky one: it DMAs from page $08 — which chapter 11’s mirrors fold onto page $00 — and checks the copy heard the echo. A hose that grabbed at raw memory instead of reading through the bus would fail it. cargo test: eighty-two green.

Try it

  • Finish level 1 for real this time. You’ve earned the right to see the WELL DONE screen.
  • Lan Master’s controls are in the manual that came in its zip — the game is a gentle puzzle about wiring computers together, which feels thematically appropriate.
  • Make transparency visible: paint color-0 pixels hot pink instead of skipping them, and every sprite shows its true square. Undo it and appreciate the hole.
  • Light a dark bit: implement attribute bit 6, horizontal flip, and prove it works — no game here will do it for you, but oam is just an array; a test can park one flipped sprite and read the pixels back.

For the curious

What stayed on the shelf: the real PPU refuses to draw more than eight sprites per scanline (the ninth winks out — the famous NES flicker is games rotating which eight lose); a status flag reports the overflow; “behind” sprites duck under the scenery; a doubled-height 8×16 mode exists; and sprite 0 has a super-power — the PPU raises a flag the instant one of its opaque pixels overlaps the background, which is how games split the screen into a fixed scoreboard over a scrolling world. Each waits for a game that demands it. Our two don’t — they were checked, sprite by sprite — and the day one does, its title screen will tell on us exactly the way Chase’s did in chapter 15.
