Build Your Own NES Emulator

Remembering where you were

Chapter 7’s loop runs in a circle it was born in: the jump targets are burned into the program. But real programs are built from helpers — draw a tile, play a note, add the score — each used from a dozen places. A helper needs to answer one question the CPU can’t yet: when I’m done… where was I?

Today the CPU gets a memory for exactly that. It’s called the stack, it’s the reason SP has been riding along since chapter 4, and it is sneakily one of the great inventions of computing.

A stack of plates

Picture a pile of plates. You can put a plate on top, and you can take the top plate off. That’s all — no sliding one out of the middle. Whatever went on last comes off first.

That discipline has a name — a stack — and it’s precisely the shape of the “where was I?” problem. Call a helper: put your return place on the pile. The helper calls another helper: another plate on top. Each return takes the top plate — and every one is, automatically, the right one. Nesting for free, to any depth. That’s the whole trick, and the rest of the chapter is just plumbing it.

Page one

The 6502 keeps its plate-pile in memory, in page one — addresses $0100 to $01FF, 256 bytes reserved by the chip’s design. SP, the stack pointer, holds the low byte of the next free slot. And one delightful quirk: the pile grows downward. The first push lands at $01FD and SP steps down to $FC; pull steps back up. Top of the pile = lowest address used. Upside-down plates, working perfectly.

/// Push one byte onto the stack. The stack lives in page one,
/// $0100-$01FF; SP points at the NEXT free slot; and the pile grows
/// DOWNWARD - push writes, then steps down.
fn push(&mut self, value: u8) {
    self.write(0x0100 + self.sp as u16, value);
    self.sp = self.sp.wrapping_sub(1);
}

/// Pull one byte back off the stack: step up, then read.
/// (Most of the world says "pop"; the 6502 says "pull".)
fn pull(&mut self) -> u8 {
    self.sp = self.sp.wrapping_add(1);
    self.read(0x0100 + self.sp as u16)
}

/// Push a two-byte value: big half first, so that in memory it lies
/// little end first - the way the 6502 likes its addresses.
fn push_word(&mut self, value: u16) {
    self.push((value >> 8) as u8);
    self.push(value as u8);
}

/// Pull a two-byte value pushed by `push_word`.
fn pull_word(&mut self) -> u16 {
    let low = self.pull() as u16;
    let high = self.pull() as u16;
    (high << 8) | low
}

/// Almost every instruction ends the same way: the CPU looks at the
/// value it just produced and updates two flags about it.

The word version comes big-half-first so the address ends up little-end-first in memory — even the stack keeps chapter 4’s byte order.

And a chapter 4 promise comes due: why did reset set SP to $FD, not $FF? Because the real chip’s reset sequence is three pushes in disguise — it runs its power-on routine through the same circuitry that pushes, stepping SP from $00 down past $FF and $FE to $FD, without actually writing anything. Strange, true, and exactly what nestest will expect in chapter 12.

Saving your stuff

The simplest use of a stack: a pocket is precious and you want it back later. Four instructions, no operands. Add the arms after the branch family:

src/cpu.rs

0x50 => self.branch_if(self.status & FLAG_OVERFLOW == 0), // BVC
0x70 => self.branch_if(self.status & FLAG_OVERFLOW != 0), // BVS

// PHA / PLA — PusH A onto the stack, PuLl it back.
0x48 => self.push(self.a),
0x68 => {
    self.a = self.pull();
    self.update_zero_and_negative(self.a);
}

// PHP / PLP — PusH and PuLl the Processor status itself,
// notes and all. Two ghost bits ride along: bits 4 and 5 exist
// only on pushed copies — PHP pushes them as ones, and PLP
// politely ignores them.
0x08 => self.push(self.status | 0b0011_0000),
0x28 => {
    let value = self.pull();
    self.status = (value | 0b0010_0000) & !0b0001_0000;
}

PHA/PLA park A and retrieve it — the classic move before and after using A for something else. PHP/PLP do the same for the status byte, notes and all: run a comparison now, act on it later, even if a dozen flag-touching instructions happen in between. (The “ghost bits” in the comment are real 6502 lore1 — harmless today, graded in chapter 12.)

Calling and coming back

Now the stars. JSR — Jump to SubRoutine — is JMP plus a note: push where I was, then go. RTS — ReTurn from Subroutine — is the mirror: read the note, resume. Add both arms after PHP/PLP’s:

src/cpu.rs

    self.status = (value | 0b0010_0000) & !0b0001_0000;
}

// JSR — Jump to SubRoutine: leave a return note on the
// stack, then go. The 6502's quirk: the note is the address
// of JSR's own LAST byte — one short of the next
// instruction. RTS knows, and adds the 1 back.
0x20 => {
    let target = self.operand_address(AddressingMode::Absolute);
    self.push_word(self.pc.wrapping_sub(1));
    self.pc = target;
}

// RTS — ReTurn from Subroutine: read the note, add the
// missing 1, resume as if nothing happened.
0x60 => {
    let return_address = self.pull_word();
    self.pc = return_address.wrapping_add(1);
}

// TAX — Transfer A to X. A keeps its value; X gets a copy.
0xAA => {
    self.x = self.a;

One genuine oddity, worth reading twice: JSR does not push the address of the next instruction. It pushes the address of its own last byte — one short. RTS adds the missing 1 after pulling. Why? Because inside the real chip, JSR’s push happens while the instruction is still being fetched, before PC has moved past it. Two quirks that cancel out — as long as every emulator author implements both halves. Our test will pin the pushed bytes exactly, because chapter 12’s golden log certainly will.

A program with manners

Time to see a helper get reused. Replace the demo program in cpu_demo with:

src/main.rs

/// Load a little machine-code program, wake the CPU, run it to the end,
/// and print every pocket after every instruction.
fn cpu_demo() {
    // One helper routine, called from TWO different places — and thanks
    // to the stack, each call comes back to the right place.
    //
    // addr   bytes     meaning
    // 8000   A9 05     LDA #5      start A at 5
    // 8002   20 09 80  JSR $8009   call the helper...
    // 8005   20 09 80  JSR $8009   ...call it AGAIN
    // 8008   00        BRK         done
    // 8009   18        CLC         the helper: add 10 to A...
    // 800A   69 0A     ADC #10
    // 800C   60        RTS         ...and go back to whoever called
    let program = [
        0xA9, 0x05, 0x20, 0x09, 0x80, 0x20, 0x09, 0x80, 0x00, 0x18, 0x69, 0x0A, 0x60,
    ];

    let mut cpu = Cpu::new();

The helper at $8009 adds 10 to A. The main program calls it from $8002, and then from $8005 — same helper, different return addresses. cargo run:

  pc     a  x  y
  ---------------
  8002   05 00 00
  8009   05 00 00
  800A   05 00 00
  800C   0F 00 00
  8005   0F 00 00
  8009   0F 00 00
  800A   0F 00 00
  800C   19 00 00
  8008   19 00 00
  8009   19 00 00
  (BRK: the program is done)

Follow the pc column: into $8009, back to $8005; into $8009 again, back to $8008. Two visits, two different homes, both found — because each JSR left its own plate on the pile. And A tells the arithmetic: 5, 15 (0F), 25 (19).

You have just watched a function call. Every function you have ever written in any language compiles down, eventually, to this pair of moves: note where you were, go; read the note, come back.

Did it work?

Seven promises, some of them fussy on purpose — add them after the chapter 7 tests:

src/cpu.rs

        let cpu = run_program(&[0xA9, 0x00, 0xAA, 0xE8, 0xE0, 0x03, 0xD0, 0xFB, 0x00]);
        assert_eq!(cpu.x, 3);
    }

    #[test]
    fn pha_pla_round_trip() {
        // LDA #7, PHA, LDA #0, PLA — the 7 survives the trip.
        let cpu = run_program(&[0xA9, 0x07, 0x48, 0xA9, 0x00, 0x68, 0x00]);
        assert_eq!(cpu.a, 7);
    }

    #[test]
    fn the_stack_is_last_in_first_out() {
        // Push 1, push 2 — then the pulls give 2 first, 1 second.
        let cpu = run_program(&[0xA9, 0x01, 0x48, 0xA9, 0x02, 0x48, 0x68, 0xAA, 0x68, 0x00]);
        assert_eq!(cpu.x, 2); // first pull (parked in X)
        assert_eq!(cpu.a, 1); // second pull
    }

    #[test]
    fn the_stack_lives_in_page_one() {
        // One push: the byte lands at $0100 + SP's old value ($FD),
        // and SP steps down to $FC.
        let cpu = run_program(&[0xA9, 0x07, 0x48, 0x00]);
        assert_eq!(cpu.read(0x01FD), 7);
        assert_eq!(cpu.sp, 0xFC);
    }

    #[test]
    fn jsr_notes_the_address_of_its_own_last_byte() {
        // JSR $8004 jumps to a BRK. The pushed note reads $8002 —
        // one short of the next instruction at $8003. RTS compensates.
        let cpu = run_program(&[0x20, 0x04, 0x80, 0x00, 0x00]);
        assert_eq!(cpu.read(0x01FD), 0x80); // big half
        assert_eq!(cpu.read(0x01FC), 0x02); // little half
    }

    #[test]
    fn jsr_and_rts_come_back_twice() {
        // A helper that adds 10, called twice — each RTS finds its own
        // way home.
        let cpu = run_program(&[
            0xA9, 0x05, 0x20, 0x09, 0x80, 0x20, 0x09, 0x80, 0x00, 0x18, 0x69, 0x0A, 0x60,
        ]);
        assert_eq!(cpu.a, 25);
    }

    #[test]
    fn php_and_plp_carry_the_notes_across() {
        // LDA #0 raises Zero; PHP saves the notes; LDA #1 clears it;
        // PLP brings the saved notes back.
        let cpu = run_program(&[0xA9, 0x00, 0x08, 0xA9, 0x01, 0x28, 0x00]);
        assert!(cpu.status & FLAG_ZERO != 0);
    }

    #[test]
    fn php_pushes_the_two_ghost_bits_as_ones() {
        // The pushed copy of status always shows bits 4 and 5 set.
        let cpu = run_program(&[0x08, 0x00]);
        assert_eq!(cpu.read(0x01FD) & 0b0011_0000, 0b0011_0000);
    }
}

The fussiest is jsr_notes_the_address_of_its_own_last_byte: it checks the exact bytes JSR leaves in page one, off-by-one quirk and all. That’s not pedantry — it’s insurance. cargo test: thirty-five green.

Try it

  • Make the helper double A instead (hint: park A somewhere in zero page with STA, then ADC it right back — and mind the Carry). What does the trace show A becoming?
  • Nest the calls: write a second helper that calls the first one twice, and call it from main. Watch the pc column come home through two layers.
  • Break it on purpose: swap RTS for BRK inside the helper, run, and look at where the program stops. The return note is still sitting on the stack, unread. Who cares? (Chapter 18 will.)

For the curious

What happens if you push 257 times? SP wraps from $00 back to $FF and the pile starts overwriting its own oldest plates — a stack overflow, the bug famous enough to name a website. The 6502 doesn’t warn you. Nothing warns you. Real NES games budget their stack the way they budget everything else: by hand, and occasionally, spectacularly, wrong.

  1. Bits 4 and 5 of the status byte aren’t real flags — there is no fifth and sixth lamp inside the chip. They only exist on pushed copies of the status, where both read as 1 when PHP does the pushing. PLP, going the other way, ignores them.
