Build Your Own NES Emulator

Controllers

Chapter 15 ended with a game on screen asking for a player. PRESS START, it says — and nobody can, because our machine has no buttons. This chapter fixes that. We’ll build the controller, plug it into the bus, and borrow your keyboard for its buttons. It’s a short chapter, and at the end of it you’ll be inside the game. Mostly.

The locked door

So how would a game notice a button? The CPU can do exactly one thing: read and write addresses. So the console gives buttons an address. Sixty times a second, Chase asks $2002 “is it vblank?” — and, the same way, it asks $4016 “what is the player pressing?”. Up on that title screen it has been asking all along. Our bus answers 0. Forever. The door is locked from the outside.

Eight buttons on one wire

The thing we’re about to build is the gray brick you may know from photos: a cross of four arrows for the left thumb, round A and B for the right, Select and Start in the middle. Eight buttons — exactly one byte’s worth, so you’d expect the game to read them all in one gulp. It can’t, and the cable is why: a wire for every button would make it thick, stiff and expensive, and 1983 said no. The pad got one data wire, a tiny chip, and a rule: the buttons answer one at a time, like names read off a list:

The write side is the strobe — from the flashing light of the same name: a quick pulse, over in an instant. While the game holds it high, the chip stares at the buttons; the moment the game drops it, whatever it saw freezes. Reads then walk the frozen list, first button to last, one bit each. So the full ritual a game performs at $4016 reads: write 1 (stare), write 0 (freeze), then read eight times. Why freeze at all? Fairness: the player can mash mid-frame, but the game’s eight reads all describe one single instant.

A snapshot, one bit at a time

The whole device fits in a page. New file, src/controller.rs:

src/controller.rs

//! The controller — eight buttons on one wire, read a bit at a time.

use std::cell::Cell;

/// One NES controller. All eight buttons fit in one byte, in the
/// order the console shifts them out: A, B, Select, Start, Up, Down,
/// Left, Right — A in bit 0, Right in bit 7.
pub struct Controller {
    /// What the player is holding at this instant. The window loop
    /// keeps this fresh; the game never sees it directly.
    pub buttons: u8,

    /// The frozen copy the game actually reads, taken the moment the
    /// strobe drops.
    snapshot: u8,

    /// The "stare at the buttons" line. High: the pad watches the
    /// buttons live. Dropped: the snapshot freezes.
    strobe: bool,

    /// Which bit of the snapshot the next read hands out. A `Cell`,
    /// for the same reason as the PPU's address: reading moves it.
    index: Cell<u8>,
}

impl Controller {
    pub fn new() -> Controller {
        Controller {
            buttons: 0,
            snapshot: 0,
            strobe: false,
            index: Cell::new(0),
        }
    }

    /// A write to $4016. Only bit 0 matters: raising it makes the pad
    /// stare at the buttons; dropping it freezes what it saw and
    /// rewinds to the first button.
    pub fn write(&mut self, value: u8) {
        let high = value & 1 != 0;
        if self.strobe && !high {
            self.snapshot = self.buttons;
            self.index.set(0);
        }
        self.strobe = high;
    }

    /// A read from $4016: the next button of the snapshot, low bit of
    /// the answer. While the strobe is high there IS no "next" —
    /// every read reports A, live. And past the eighth button a real
    /// pad answers 1, which is how games tell a controller from an
    /// empty port.
    pub fn read(&self) -> u8 {
        if self.strobe {
            return self.buttons & 1;
        }
        let index = self.index.get();
        if index < 8 {
            self.index.set(index + 1);
            (self.snapshot >> index) & 1
        } else {
            1
        }
    }
}

One field wears a Cell, and after chapter 15 you can smell why from across the room: reading is touching. Every read of $4016 walks the snapshot forward one button — polite reads, like polite writes, leave footprints.

Keys to buttons

The console end is done; now the human end. Once per frame, before the game runs, gather the keyboard into a button byte — at the top of the if let Some(cpu) in the window loop:

src/main.rs

// paint what it described. The instruction counts are a crude
// stand-in for real timing — chapter 18 earns the real thing.
if let Some(cpu) = &mut machine {
    // The keyboard becomes the controller — one key per
    // button, in the console's own order: A, B, Select,
    // Start, then the four directions.
    let keys = [
        Key::X,     // A
        Key::Z,     // B
        Key::Space, // Select
        Key::Enter, // Start
        Key::Up,
        Key::Down,
        Key::Left,
        Key::Right,
    ];

    let mut buttons = 0;
    for (bit, key) in keys.iter().enumerate() {
        if window.is_key_down(*key) {
            buttons |= 1 << bit;
        }
    }

    cpu.bus.controller.buttons = buttons;

    for _ in 0..10_000 {
        cpu.step();
    }

X and Z for A and B is an old emulator habit: right hand on the letters like thumbs on the pad, left hand on the arrows. Remap to taste — the game only ever sees the byte.

Press START

cargo run roms/Chase.nes. The title. Press Enter.

The PRESS START line flickers madly, the screen dips to black, and a proud blue LEVEL 1 rises. Then the arena fades in: walls, a field of gems, and a scoreboard — LEVEL, GEMS 000/020, LIVES 3. You are standing in a game that has been unreachable since chapter 11.

Now the strangeness starts. Hold an arrow key. Nothing visible moves — but gems start vanishing, one after another, and the GEMS counter climbs. That’s you. You are the nothing eating them, and the trail of missing gems is your wake. Let go of the keys and stand still a while: the picture dissolves, LEVEL 1 rises again, and LIVES says 2. You never saw what got you.

Every part of the game is running — your hero, the hunter, collisions, the score. The world is a ghost town because all of its inhabitants are drawn by a PPU circuit we haven’t built: sprites. The background is the scenery; everything that moves rides on top. One chapter from now the ghosts get bodies, and you’ll want your reflexes ready — because that hunter has been practicing on you.

#[cfg(test)]
mod tests {
    use super::*;

    /// A controller holding `buttons`, strobed the way games do it:
    /// stare, then freeze.
    fn frozen(buttons: u8) -> Controller {
        let mut controller = Controller::new();
        controller.buttons = buttons;
        controller.write(1);
        controller.write(0);
        controller
    }

    #[test]
    fn buttons_come_out_one_bit_at_a_time_a_first() {
        // Start is bit 3, Right is bit 7.
        let controller = frozen(0b1000_1000);
        let bits: Vec<u8> = (0..8).map(|_| controller.read()).collect();
        assert_eq!(bits, [0, 0, 0, 1, 0, 0, 0, 1]);
    }

    #[test]
    fn past_the_eighth_button_a_real_pad_answers_one() {
        let controller = frozen(0);
        for _ in 0..8 {
            controller.read();
        }
        assert_eq!(controller.read(), 1);
        assert_eq!(controller.read(), 1);
    }

    #[test]
    fn the_snapshot_freezes_when_the_strobe_drops() {
        let mut controller = frozen(0b0000_0001);
        // Released after the freeze — too late, the read still says A.
        controller.buttons = 0;
        assert_eq!(controller.read(), 1);
    }

    #[test]
    fn while_the_strobe_is_high_every_read_reports_a() {
        let mut controller = Controller::new();
        controller.buttons = 0b0000_0001;
        controller.write(1);
        assert_eq!(controller.read(), 1);
        // Still A. Staring is not stepping.
        assert_eq!(controller.read(), 1);
    }

    #[test]
    fn a_fresh_strobe_rewinds_to_the_first_button() {
        let mut controller = frozen(0b0000_0010);
        controller.read();
        controller.read();
        controller.write(1);
        controller.write(0);
        assert_eq!(controller.read(), 0); // A again...
        assert_eq!(controller.read(), 1); // ...then B.
    }
}

The freeze test is the one to savor: buttons released after the strobe drops don’t change the answer, exactly the fairness the hardware promises. cargo test: eighty green.

Try it

  • Try to finish the level blind: 20 gems, dodging a hunter you can’t see. It’s genuinely possible and genuinely terrifying.
  • Boot Lan Master and press Enter: LEVEL01, a timer, and a board of network pieces — a whole puzzle game made of scenery. What’s missing here is smaller than in Chase: just the pointing hand you’d move. Ghost towns come in sizes.
  • Remap the keys. WASD players, this is your moment.
  • Wire the second port: another Controller at $4017, with keys of its own. Neither of our games reads it, but the console has two ports and now so do you.

For the curious

Chase’s pad routine reads the controller three times per frame and keeps a pair that matches. Paranoia? Experience. On a real NES, the sound chip’s sample channel pauses the CPU to fetch audio bytes, and if that pause lands mid-ritual the read can lose a bit — a phantom button press, or a real one deleted. Games shipped the re-read as armor. Our machine’s reads never glitch, so the armor just makes the same snapshot three times — but it’s a preview of a Part II truth: on this console, even audio can bend input.
