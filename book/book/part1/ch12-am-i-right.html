Build Your Own NES Emulator

Am I right?

Fifty-six tests, all green. A real game boots. And still — how would you know? A CPU has 151 instructions times eight-ish flavors times seven flags; somewhere in that space, at least one of your arms is wrong in a way no green test has met yet. Every emulator author reaches this exact cliff, stares down, and asks the scariest question in the whole project: am I right?

You cannot eyeball your way to the answer. What you can do is compare — against someone who is known to be right. This chapter does precisely that, and by the end your CPU will have been checked, instruction by instruction, five thousand times in a row. Along the way it will fail twice. That’s not the sad part of the chapter. That’s the point of it.

A ROM that grades you

Meet nestest, a test ROM written by kevtris — a legend of the NES community — that methodically exercises the whole official instruction set. Download nestest.nes, and alongside it the famous golden log: nestest.log, a recording of a known-good emulator running that ROM, one line per instruction, state laid bare. Put both in your roms/ folder. (Both are linked from the NesDev wiki’s emulator-tests page, which is the community’s front door for this material.)

nestest has a magic trick documented in its manual: started at address $C000 instead of through the reset vector, it runs in automation mode — no picture chip needed, which is lucky, since we don’t have one. Look at the log’s first line:

C000  4C F5 C5  JMP $C5F5                       A:00 X:00 Y:00 P:24 SP:FD PPU:  0, 21 CYC:7

Address, raw bytes, the instruction’s name, every register. Our plan writes itself: make our emulator produce the same diary, then compare line by line. The first difference is the truth.

    /// One line of diary: where the CPU is, the instruction it is about
    /// to run, and the state of every pocket — before the deed.
    pub fn trace(&self) -> Option<String> {
        let opcode = self.read(self.pc);
        let (name, length) = Cpu::opcode_name_and_length(opcode)?;

        // The instruction's raw bytes, as many as it has.
        let mut bytes = String::new();
        for offset in 0..length {
            let byte = self.read(self.pc.wrapping_add(offset));
            bytes.push_str(&format!("{byte:02X} "));
        }

        Some(format!(
            "{:04X}  {:<9} {}  A:{:02X} X:{:02X} Y:{:02X} P:{:02X} SP:{:02X}",
            self.pc, bytes, name, self.a, self.x, self.y, self.status, self.sp
        ))
    }
}

/// Run nestest in automation mode and grade our CPU against a golden
/// log, line by line. The first difference is the truth.
fn nestest_diff(rom_path: &str, log_path: &str) {
    let bytes = std::fs::read(rom_path).expect("could not read the ROM");
    let cartridge = Cartridge::load(&bytes).expect("could not parse the ROM");
    let golden = std::fs::read_to_string(log_path).expect("could not read the log");

    let mut cpu = Cpu::new(cartridge);
    cpu.reset();
    // nestest's automation mode: start at $C000 instead of the vector,
    // and the tests run with no picture chip needed at all.
    cpu.pc = 0xC000;

    let mut matched = 0;
    for line in golden.lines() {
        // The fields both sides have: PC and the five pockets. (The log
        // also carries cycle counts — a Part II subject.)
        let ours = format!(
            "{:04X} A:{:02X} X:{:02X} Y:{:02X} P:{:02X} SP:{:02X}",
            cpu.pc, cpu.a, cpu.x, cpu.y, cpu.status, cpu.sp
        );
        let theirs = format!("{} {}", &line[0..4], &line[48..73]);

        if ours != theirs {
            println!("MISMATCH after {matched} matching lines.");
            println!("  golden: {theirs}");
            println!("  ours:   {ours}");
            println!("  the golden line in full:");
            println!("  {line}");
            return;
        }
        matched += 1;

        if Cpu::opcode_name_and_length(cpu.read(cpu.pc)).is_none() {
            println!(
                "{matched} lines matched — then {:#04X}, an opcode we",
                cpu.read(cpu.pc)
            );
            println!("don't implement. Unofficial. A Part II story.");
            return;
        }
        cpu.step();
    }
    println!("all {matched} lines matched");
}

The first catch

Deep breath.

$ cargo run roms/nestest.nes roms/nestest.log

thread 'main' panicked:
I don't know opcode 0x40 yet!

Our own stop sign, from chapter 5 — stopping loudly beats carrying on wrongly — and it just earned its keep. Opcode $40 is RTI, return from interrupt: the one instruction we deferred. How far did we get? Ask the log — search it for RTI:

934: CEAD  40        RTI      A:55 X:99 Y:88 P:A5 SP:7D ...

Nine hundred and thirty-three lines matched before that. Your CPU ran a stranger’s test gauntlet — every flag of every ADC, the ghost bits of every PHP — for 933 instructions without missing once. And nestest, it turns out, doesn’t wait for chapter 18: it builds an interrupt’s stack frame by hand and demands the return trip. Which reveals something pleasant: RTI needs no interrupt machinery at all. It’s pure chapter 8 — pull the status (ghost-bit manners, like PLP), pull the address. Add its arm after RTS’s:

src/cpu.rs

    self.pc = return_address.wrapping_add(1);
}

// RTI — ReTurn from Interrupt: pull the status notes back
// (ghost-bit manners, as with PLP), then pull the address —
// EXACTLY as saved, no +1. JSR pushes one short and RTS
// compensates; an interrupt pushes the true address, so RTI
// adds nothing. Two callers, two manners.
0x40 => {
    let value = self.pull();
    self.status = (value | 0b0010_0000) & !0b0001_0000;
    self.pc = self.pull_word();
}

// LDX and LDY — every flavor each of them is sold in.
0xA2 => self.ldx(AddressingMode::Immediate),
0xA6 => self.ldx(AddressingMode::ZeroPage),

Note what it doesn’t do: no +1. JSR pushes an address one short and RTS compensates; interrupts push the true address, so RTI adds nothing. Two callers, two manners — and a test to pin it, after the ghost-bits test:

src/cpu.rs

    let cpu = run_program(&[0x08, 0x00]);
    assert_eq!(cpu.read(0x01FD) & 0b0011_0000, 0b0011_0000);
}

#[test]
fn rti_pulls_status_and_the_exact_address() {
    // Hand-build an interrupt's stack frame — PC $800A, then a
    // status byte — and RTI must land exactly there, notes
    // restored, no +1. The BRK at $800A catches the landing.
    let cpu = run_program(&[
        0xA9, 0x80, 0x48, // LDA #$80, PHA — address, big half
        0xA9, 0x0A, 0x48, // LDA #$0A, PHA — address, little half
        0xA9, 0x02, 0x48, // LDA #$02, PHA — a status with Z raised
        0x40, // RTI
        0x00, // $800A: BRK
    ]);
    assert_eq!(cpu.pc, 0x800B); // the BRK at $800A fetched, stopped
    assert!(cpu.status & FLAG_ZERO != 0); // the pulled Z came back
}

The second catch

Run the grader again:

$ cargo run roms/nestest.nes roms/nestest.log

MISMATCH after 1100 matching lines.
  golden: CFF4 A:5D X:00 Y:69 P:25 SP:FB
  ours:   CFF4 A:04 X:00 Y:69 P:25 SP:FB
  the golden line in full:
  CFF4  C9 5D     CMP #$5D                        A:5D X:00 Y:69 P:25 SP:FB PPU: 22,271 CYC:2591

Read the crime scene like a detective. The golden machine reached $CFF4 holding A:5D; ours arrived holding A:04. So the instruction before loaded A wrongly — back up one line in the log:

1100: CFF2  A1 FF     LDA ($FF,X) @ FF = 0400 = 5D    ...

LDA ($FF,X) — an indirect load, pointer at the very edge of the zero page. And the log’s decorations spell out what the real chip did: @ FF = 0400 — pointer at $FF, target $0400. Look at that target. The pointer’s low half came from $FF… so its high half came from $00. The real chip wraps inside the zero page. Our chapter 6 code calls read_word($FF), which happily reads $FF and $100 — off the edge.

A confession: I knew. That bug was left in chapter 6 deliberately, unmarked, so you could feel this exact moment — shipping a wrong-in-one-case emulator, believing it right for five chapters, and being caught not by a crash but by a comparison. This is what golden logs are for, and no other kind of test would have found it this fast.

The fix — replace both pointer-following arms in operand_address:

src/cpu.rs

            self.pc = self.pc.wrapping_add(2);
            base.wrapping_add(self.y as u16)
        }
        // ($xx,X): add X to the zero-page spot, THEN follow the
        // pointer stored there. BOTH pointer bytes come from the
        // zero page: a pointer starting at $FF takes its second
        // half from $00, never $0100. nestest taught us this one.
        AddressingMode::IndirectX => {
            let base = self.read(self.pc);
            self.pc = self.pc.wrapping_add(1);
            let pointer = base.wrapping_add(self.x);
            let low = self.read(pointer as u16) as u16;
            let high = self.read(pointer.wrapping_add(1) as u16) as u16;
            (high << 8) | low
        }
        // ($xx),Y: follow the pointer at the zero-page spot — same
        // wrap — THEN add Y to wherever it led.
        AddressingMode::IndirectY => {
            let base = self.read(self.pc);
            self.pc = self.pc.wrapping_add(1);
            let low = self.read(base as u16) as u16;
            let high = self.read(base.wrapping_add(1) as u16) as u16;
            ((high << 8) | low).wrapping_add(self.y as u16)
        }
    }
}

#[test]
fn indirect_y_pointer_at_ff_wraps_inside_the_zero_page() {
    // The pointer's low half sits at $FF; its high half comes from
    // $00 — never $0100. A decoy waits on the wrong path.
    let cpu = run_program_with(
        &[0xB1, 0xFF, 0x00],
        &[
            (0x00FF, 0x00), // pointer, little half
            (0x0000, 0x03), // pointer, big half — the LAWFUL one
            (0x0100, 0x07), // the wrong big half, lying in wait
            (0x0300, 0x2A), // the prize, where the law leads

    assert_eq!(cpu.a, 0x2A);
}

fn nestest_matches_the_golden_log() {
    // Runs only when both files sit in roms/ — the robots skip
    // politely on machines without them. (`let ... else`: destructure
    // or bail.)
    let (Ok(bytes), Ok(golden)) = (
        std::fs::read("roms/nestest.nes"),
        std::fs::read_to_string("roms/nestest.log"),
    ) else {
        return;
    };

    let mut cpu = Cpu::new(Cartridge::load(&bytes).unwrap());
    cpu.reset();

    let mut matched = 0;
    for line in golden.lines() {

For the curious

The two columns we ignored — PPU: 22,271 CYC:2591 — are clocks: how many cycles each instruction cost and where the picture chip’s beam was while it ran. Our emulator matches every state and none of the timing, because it has no notion of time at all: every instruction is instant. For running Chase’s menu, that’s fine — but not forever. Chapter 18 makes the CYC column real; the beam’s column is Part II’s, for the games that change the picture mid-frame.
