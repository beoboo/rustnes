Build Your Own NES Emulator

Real time

Confession. Since chapter 15, a “frame” in our machine has been 10,000 instructions, then vblank, then 1,000 more — numbers I picked because they were round and the title screen came up. The games play, so who cares? The console does. A real NES doesn’t count instructions; it counts cycles, the tick of a quartz crystal at 1,789,773 beats a second, and every instruction costs its own particular number of them. Two games agreeing to meet “at frame 500” arrive at different moments on our machine and on real silicon. This chapter throws out the round numbers and gives the machine its true clock — and pays off two debts that have waited since the single digits: BRK’s, and the golden log’s last column.

The anatomy of a frame

Where does a frame’s length even come from? From the television. The beam draws 262 scanlines, each 341 dots wide, and the picture chip emits exactly one dot per tick of its clock — which runs at three ticks for every CPU cycle. Divide it all out:

Those two numbers — roughly 27,393 cycles of painting, roughly 2,387 of rest — replace our 10,000 and 1,000. Not instructions. Cycles.

The price list

So how much does one instruction cost? The 6502’s designers published it, opcode by opcode, and emulator builders have been copying it out ever since. First, somewhere to count: two new pockets at the bottom of the Cpu struct, under status:

Read a few prices and the chip’s personality shows. Register-to-register moves: 2, the minimum, one cycle to fetch and one to think. A zero-page read: 3. A full-address read: 4. The read-modify-write family — INC, the shifts — 5 to 7, because the chip reads, chews, and writes back. JSR: 6, the price of pushing a return note. Surcharges

Three costs the table can’t hold, because they depend on what the instruction finds.

The first: indexed reads. LDA $80F0,X promises 4 cycles — but if adding X carries into the address’s top byte, the chip needs an extra cycle to fix it up. The question “did it carry?” comes up often enough this chapter to deserve its own words — after the price list:

/// Do two addresses sit on different pages? A "page" is a 256-byte
/// stretch of memory: same top byte, same page. The 6502 computes
/// addresses a byte at a time, so stepping over a page edge means
/// extra work for it — and surcharges for us.
fn crosses_a_page(from: u16, to: u16) -> bool {
    from & 0xFF00 != to & 0xFF00
}

The second cost is a non-cost, and it’s a trap: writers never pay the surcharge. The chip can’t risk storing to a half-fixed address, so a store burns the fix-up cycle whether it crosses or not — and the price list already charges it (STA absolute-X: 5, no asterisk). Two flags to lower, in sta after the address is found:

src/cpu.rs

/// No flags — storing changes memory, not the CPU's mood.
fn sta(&mut self, mode: AddressingMode) {
    let address = self.operand_address(mode);

    // Writers never pay the crossing surcharge — the price list
    // charges them the worst case up front, crossing or not.
    self.crossed = false;

    self.write(address, self.a);
}

— and the same line in modify:

src/cpu.rs

/// name is a value you can pass around, like any other.
fn modify(&mut self, mode: AddressingMode, worker: fn(&mut Cpu, u8) -> u8) {
    let address = self.operand_address(mode);

    // Read-modify-write pays the worst case up front, like STA.
    self.crossed = false;

    let value = self.read(address);
    let result = worker(self, value);
    self.write(address, result);

The third: branches. Declined, a branch is the flat 2. Taken, it costs one more — and two more if the jump lands on a different page. In branch_if, replace the taken case:

src/cpu.rs

    self.pc = self.pc.wrapping_add(1);

    if condition {
        // A branch NOT taken is the cheap case on the price list.
        // Taking it costs one extra — and one more on top if the
        // jump lands on a different page.
        let target = self.pc.wrapping_add(offset as u16);
        self.cycles += 1;
        if crosses_a_page(self.pc, target) {
            self.cycles += 1;
        }
        self.pc = target;
    }
}

Try it

  • Add a frame counter and a cycle counter to the window title. Watch the cycles tick up by exactly 29,780 a frame, forever.
  • Break something on purpose: charge LDA immediate 3 cycles instead of 2 and run the grader. Marvel at how fast the very first LDA gets caught.
  • The frame loop finishes an instruction even when the budget runs out mid-way — a frame boundary never splits an instruction. Real hardware agrees: interrupts wait for the current instruction too. Prove it: log cpu.cycles % 29_780 at each frame’s end and watch the tiny overshoot wobble.

For the curious

Our frame is 29,780 cycles; a real NTSC frame is 29,780 and a half — the PPU’s 341 dots per line don’t divide by 3. The half-cycle wobble is why long recordings of real consoles slowly drift against a stopwatch, and why serious emulators run the PPU dot by dot instead of letting the CPU lead. That per-dot machine is Part II’s centerpiece — and it’s also what sprite 0’s mid-frame flag and the scroll tricks are waiting for.
